## 模块二：叙事主线打磨（下午，2h）

### 3 分钟版（用于自我介绍/"介绍一下你自己"）

结构：**一句话定位 → 最强项目（30 秒数字）→ 方法论抽象 → 与岗位的连接**

> "我是十年经验的系统工程师，最近三年在华为昇腾做 AI 算子优化。最有代表性的工作是大模型权重量化 GEMM 的 kernel 优化：单核算力利用率做到 85% 以上，方法是三件事——基于访存/计算 bound 分界模型的 tiling 搜优、L2 友好的多核调度、以及手工流水线隐藏搬运延迟。更早我在钉钉负责过日活千万的审批引擎架构，处理脉冲式高并发。
>
> 我怎么看推理系统优化这个方向：**LLM serving 的核心矛盾和我做 kernel 时是同一组——decode 是访存 bound，和我优化的小 M 量化 GEMM 同构；KV cache 管理是内存问题；continuous batching 是调度问题；P/D 分离就是把 compute-bound 和 memory-bound 负载拆开各自优化**。这周我系统研究了 vLLM V1 的调度和 KV 管理，还手写了 mini serving 引擎验证理解。我希望把底层的算力压榨能力和上层的系统设计能力在这件事上合流。"

### 10 分钟版（用于项目深讲）

在 3 分钟版基础上，把"最强项目"展开为 STAR：
- **S**：千亿模型推理场景，量化 GEMM 是 decode 热点
- **T**：单核算力利用率目标 85%+
- **A**：三个技术点各讲 90 秒（ASW 模板与 L2 命中 / bound 分界模型的 tiling 搜优 / 无 Queue 手工流水线）——**每个点都要有一句"为什么这么做"和"放弃了什么"**（trade-off 是专家信号）
- **R**：量化结果 + 这套方法论如何迁移（接到 vLLM 话题）

### 预期刁难问题与应对

| 刁难 | 应对 |
|---|---|
| "你没在生产环境用过 vLLM 吧？" | 承认 + 转化："生产经验没有，但我读过 scheduler 和 KV 管理的核心源码、手写了简化引擎、做过 X 组压测——给我两周我能跟上，因为我的底层功底不需要补" |
| "CUDA 写过吗？" | 诚实："主要经验在 Ascend C，编程模型同构（核函数/多级存储/流水线），Triton/CUDA 的迁移我有明确路径" |
| "某个源码细节你知道吗？"（不会的） | "这块还没读到，我的推测是……因为……"——**给推理过程比给答案重要** |

## 模块三：系统设计题专项（下午，45 min 准备）

**高频题**："为一个日活千万级的客服机器人设计推理服务架构"。

**答题框架（按此顺序讲，体现方法论）**：

1. **需求量化（2 min）**：
   - 峰值 QPS 估算：DAU 1000 万 × 人均 10 轮 × 峰值系数 / 86400s ≈ 峰值数千 QPS 量级
   - 负载画像：客服场景 = 共享系统提示词（prefix caching 甜点）+ 短输出 + 明确 SLO（TTFT < 1s，TPOT < 100ms）

2. **容量规划（2 min）**：用 Day 1 公式现场估算单实例并发 → 推出实例数

3. **架构（4 min）**：
   - 入口：cache-aware 路由（同租户/同会话打向同实例，拉高 prefix 命中率）
   - 推理层：P/D 分离（prompt 短则论述"可以不分离"的权衡——主动给反方意见是加分项）
   - 实例内：continuous batching + chunked prefill + prefix caching + FP8
   - 弹性：脉冲流量 → 排队 + 优先级（付费用户），降级预案（限流/切小模型/关投机解码）

4. **可观测与保障（2 min）**：TTFT/TPOT p99 看板、preemption 告警、KV 使用率水位线
